# 可复现基准与横评方法

**作者：张三峯** ｜ 公众号：**AI龙卷风**

原则：**只发布自己跑出来的数字**。本文件不含任何竞品的实测数值；竞品数据
必须由使用者按同一方法自行测量后填入，未测量就写「待测」。

## 1. 本仓库自测基线

采集命令：`python3 tools/benchmark.py --out bench.json`；读取 `tools/check_all.sh`
的全量闸门结果。环境：macOS，Python 3.13.12，python-pptx 1.0.2、
Pillow 12.3.0、lxml 6.1.3；采集时间 2026-11-08。

| 指标 | 实测值 | 口径 |
|---|---|---|
| deck 数 | 8 | `examples/*.json` 中的合法 deck（排除素材清单与笔记/台账输入） |
| 版面硬错误总数 | 0 | `lint_deck()` 的 `errors` 累计 |
| 平均可编辑形状占比 | 0.9647 | `(全部形状 − 图片形状) / 全部形状`，对 8 份产物取均值 |
| 文字溢出率 | 0.0 | `(TEXT_OVERFLOW + RICHCARD_OVERFLOW) / 文本节点数` |
| 平均 lint 耗时 | 0.0139 s | 含 `prepare()` 布局阶段 |
| 平均编译耗时 | 0.0852 s | `build_pptx()` 单份耗时 |
| 核心管线联网调用（静态扫描） | 0 处 | `engine/*.py` 中除可选网图通道外的网络客户端命中 |
| 运行时依赖 | 3 个 | `python-pptx` / `Pillow` / `lxml` |
| 离线渲染回归 | **本机 skipped** | 未安装 LibreOffice；CI 安装后强制断言 `status=ok` |

逐 deck 可编辑占比：`demo.json` 1.0000、`deck_business_demo.json` 1.0000、
`deck_notes_composed.json` 0.9908、`deck_v2.json` / `deck_theme_*.json` 0.9545、
`deck_v3.json` 0.9091。差异来自示例页里刻意放入的图片形状。

**这些数字是本机一次运行的记录，不是性能承诺。** 换机器、换 Python 版本、
换 deck 都会变。CI 会在 4 个 Python 版本上重跑功能闸门。

## 2. 指标定义（横评必须一致）

| 指标 | 定义 | 为什么可比 |
|---|---|---|
| 版面错误数 | lint/视觉检查确认的硬错误（越界、溢出、重叠、不可读） | 直接反映「能不能交付」 |
| 可编辑率 | 原生可编辑形状 / 全部形状 | 区分「真 PPT」与「截图拼页」 |
| 文字溢出率 | 溢出文本节点 / 全部文本节点 | 中文长文本最容易翻车 |
| 离线可用性 | 核心生成链路是否发起网络请求 | 政企/内网场景硬约束 |
| 耗时 | 从输入到 .pptx 落盘的秒数 | 需注明硬件与是否含 LLM 调用 |
| 可复现性 | 同输入两次产物是否一致 | 决定能否进 CI / diff |

## 3. 横评模板（待使用者填写）

用**同一份中文材料**（建议：一份 9 页读书笔记 + 一份 8 页经营分析，各含
长段落、数字、引文、页边批注），对每个项目跑同样的输入。

| 项目 | 版本/日期 | 版面错误数 | 可编辑率 | 文字溢出率 | 离线可用 | 耗时 | 可复现 | 备注 |

| FreePPT | 20261108.3 | 0（本机自测） | 0.9647（本机自测） | 0.0（本机自测） | 是（静态扫描） | 见上 | 是 | 本仓库基线 |
| 项目 A | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 未运行 |
| 项目 B | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 未运行 |

填写规则：

1. 未亲自运行的项目一律写「待测」，**不得从宣传文章或转载横评抄数字**。
2. 记录每个项目的实际版本号 / commit 与运行日期。
3. 说明是否调用了大模型；含 LLM 的耗时与不含 LLM 的耗时不可直接比较。
4. 版面错误数必须附判定依据（lint 输出或逐页标注），不能凭印象。
5. 引用他人测量结果时按 MLA 注明来源，并明确那是二手数据。

## 4. 渲染回归

`tools/render_check.py` 把 .pptx 转 PDF → PNG，检查页数一致、每页非空白、
PDF 可提取文字。本机缺少 `soffice` 时会返回 `status: skipped`（**跳过不等于通过**）。
GitHub Actions 的 `render-regression` job 安装 `libreoffice-impress`、
`poppler-utils`、`fonts-noto-cjk` 后强制断言 `status == "ok"`，并上传逐页 PNG。

像素级基线对比（与历史 PNG 做 diff）尚未实现；当前只验证「能打开、页数对、
非空白、文字在」。这是明确的 scope 边界，不宣称做了视觉回归。

## 5. 局限

- `editable_ratio` 只数形状类型，不评价是否好看。
- `overflow_rate` 来自 lint 诊断，不是像素级测量。
- 离线可用性是静态扫描，不是运行时网络抓包。
- 竞品没有在本仓库内运行过，任何对比结论都需读者自行补齐数据。
