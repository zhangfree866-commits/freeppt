# FreePPT 内容智能创作手册（content playbook）

本手册规定 agent 如何把用户的简略文本/零散要点，扩写为符合专业咨询标准的完整 PPT。
工程侧 `engine/content_ai.py` 负责确定性的结构规划与质量把关；语言层面的扩写、润色、
逻辑梳理由 agent 按本手册执行。**禁止编造数据**：没有依据的数字一律保留占位或向用户索要。

## 一、创作五步法（与引擎五阶段对齐）

1. **解析**：`content_ai.parse_brief` 把零散输入切成干净要点，去项目符号/空行。
2. **路由**：`assign_points` 按关键词把每条要点分配到报告对应章节（指标→KPI、
   趋势→图表、问题/根因→诊断卡、计划→举措、里程碑→时间线）。
3. **扩写**：agent 按本手册把每条要点扩成完整页面内容（见下文规则）。
4. **把关**：`content_ai.check_content` 查占位残留/套话/无据主张/非结论标题/缺来源；
   再走 `cli.py lint` 查版面。两关都过才允许 build。
5. **渲染**：`cli.py build` 产出可编辑 .pptx。

## 二、专业表达四条硬规则

### 1. Action Title（结论式标题）
标题必须是**完整结论句**，不是话题标签。
- 错：「经营情况」「客户分析」「Q3 业绩」
- 对：「收入连续三个季度保持 20% 以上同比增长」「客户留存率低于目标 8 个百分点」
- 判定：去掉标点后 ≥8 字、含可判断的结论或数字；check 的 ACTION_TITLE 会预警过短标题。

### 2. 金字塔 + MECE
- 每页一个中心论点（金字塔顶层），下方论据相互独立、完全穷尽（MECE）。
- 三点式卡片必须是真分类（如「获客/转化/留存」），禁止为凑数写三个近义词。
- 论证顺序：结论先行 → 分组论据 → 数据支撑。

### 3. 数据→结论，不堆数字
- 每个数字必须回答「so what」：它说明什么趋势/问题/机会。
- 图表页 `insight` 写业务含义与建议动作，不复述图表数值。
- 无量化证据的判断会触发 WEAK_CLAIM 警告；补口径、样本或来源。

### 4. 可信性
- 图表/结论页必须填真实 `source`（公司系统/财报/第三方机构），check 的 MISSING_SOURCE 强拦。
- 时效数字、陌生术语先核实再写；查不到就标注「待核实」，不杜撰。

## 三、套话黑名单（触发 CLICHE 警告，需替换）

| 套话类型 | 示例 | 替换方向 |
|---|---|---|
| 空泛开场 | 在……背景下、众所周知、不言而喻 | 直接给结论或数据 |
| 万能动词 | 赋能、抓手、闭环、保驾护航、深度赋能 | 写清具体动作与对象 |
| 自夸无据 | 行业领先、强势、重磅、引领行业 | 加排名/份额/数据，否则删 |
| 口号收尾 | 砥砺前行、凝心聚力、高质量发展 | 换成可衡量的下阶段目标 |

## 四、扩写操作要点（按模板）

- **kpi_row**：每个指标给「数值 + 单位 + 口径」，`note` 写环比/同比与统计范围。
- **chart_insight**：`chart` 填真实序列；`insight` 是完整结论句（≥60 字）；
  `kpi` 放一个最该被记住的记忆点数字；`source` 必填。
- **three_cards**：每卡 `body` ≥40 字，含具体事实/数据/案例，三卡 MECE。
- **process**：每步写「动作 + 责任人 + 时间点」，可执行可追踪，不写方向口号。
- **timeline**：按时间顺序，每点含事件、量化结果、影响。
- **cover/section/closing**：封面主标题用结论式主题；章节页一句话定调；封底克制。

## 五、各报告类型的叙事主线

| 类型 | 主线逻辑 |
|---|---|
| 周报 weekly | 本周结果(指标) → 重点进展 → 下周计划，短平快 |
| 月报 monthly | 月度指标 → 数据解读 → 工作复盘 → 下月计划 |
| 季度报 quarterly | 季度定调 → 达成与趋势 → 战略举措 → 下季规划 |
| 年度报 annual | 年度回顾 → 战果数据 → 里程碑 → 来年展望，篇幅最完整 |
| 述职 performance | 岗位职责 → 业绩证据 → 项目贡献 → 成长与不足 → 下阶段目标 |
| 竞聘 competition | 岗位理解 → 人岗匹配优势 → 战绩背书 → 履职思路 → 上任规划 |
| 复盘 retrospective | 目标 vs 实际 → 亮点经验 → 问题根因(5Why) → 改进 action |
| 经营分析 business | 核心指标 → 收入/成本拆解 → 问题诊断 → 改善举措，重数据 |

## 六、命令速查

```bash
# 1. 生成某类报告的结构化骨架（含占位与写作提示）
python3 engine/content_ai.py skeleton business --out deck.json

# 2. 把零散要点自动路由到对应页面，生成带 _notes 的种子 deck
python3 engine/content_ai.py route business --brief-file notes.txt --out deck.json

# 3. 填完后做内容质量把关（占位/套话/无据主张/来源）
python3 engine/content_ai.py check deck.json

# 4. 版面 lint + 编译（五阶段的第 3-5 阶段）
python3 engine/cli.py lint deck.json
python3 engine/cli.py build deck.json out.pptx
```

agent 的职责边界：负责第 3 步的语言创作，并对每条写入内容的真实性负责；
结构正确性与版面质量由确定性引擎保证，不依赖临场审美。
