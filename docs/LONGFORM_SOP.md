# 长篇 Deck 生产 SOP（12 道工序）

> **适用**：30 页以上、需要分章、要求逐页不重样、备注全覆盖的长内容 PPT（培训课件 / 读书笔记 / 方法论手册 / 高管课程）。
> **来源**：11 份 85–115 页成品 + 9 条制作过程逐屏取证归纳，非推测。取证报告见会话工作区 `doubao-benchmark/`（`ELEVEN_SAMPLE_BENCHMARK.md` 为最终版）。
> **性质**：这是「**怎么做才算专业**」的作业纪律，不是引擎能力清单。引擎提供工具箱（`render` / `lint` / `verify` / `build` / `inspect`），本文件规定**这些工具在什么时机、按什么判据被调用**。

---

## 0. 先看这张总表

| # | 工序 | 一句话判据 | 不做的后果 |
|---|---|---|---|
| 0 | 读规范 | 开写前先加载本文件 + DSL 语法 + 主题令牌 | 边写边查，格式反复崩 |
| 1 | 读素材 | 有附件必看，多附件全解析 | 风格跑偏、要求漏项 |
| 2 | 出大纲 | 章节表 + 页数分配，先同步缺口 | 做到一半发现页数不够 |
| 3 | 定设计系统 | 落成可执行规格，**含禁用清单** | 越做越堆，风格失控 |
| 4 | 先做样本页 | 前 5–6 页做出、截图核对、定型 | 100 页全错要全改 |
| 5 | 分章批量 | 每批 10–15 页，**校验通过才写入** | 错误累积，最后不可收敛 |
| 6 | lint 闸门 | 每页写入前 error=0；回读全文再跑一遍 | 带病上线 |
| 7 | 误报裁定 | 阻断项截图人工核对，判定真/假阳性并留痕 | 真问题被当误报放过 |
| 8 | 回读核对 | 回读实际页数 = 规划页数，页码页序对齐 | 少页、串页 |
| 9 | 素材核验 | 图逐张核验有效性、无外链残留、无跨页重复 | 交付后图裂 |
| 10 | 截图抽查 | 抽 3–16 页核验无重叠 / 破图 / 空白 | 渲染事故漏网 |
| 11 | 缺口如实报 | 未达标就直说，不粉饰、不静默降级 | 信任崩塌 |
| 12 | 交付自述 | 页数 / 结构 / 规格 / 验收结果 / 使用建议 | 用户不知道该看什么 |

**我们原有的 7 道**：3（风格路由）、5（逐页写 DSL）、6（lint）、8（部分）、10（雏形）、12（部分）、0（部分）。
**必须补的 5 道**：**1 素材解析**、**3 的负面约束**、**7 误报裁定机制**、**9 素材核验**、**11 缺口如实上报**。

## 1. 工序 0：读规范（开写前 1 分钟）

**做什么**
1. 读本文件（你在读）。
2. 读 `references/dsl-spec.md` 或 `references/dsl.md`，确认节点白名单。
3. 读将要用的主题 token（`engine/themes.py` 里对应 id），确认调色板与字号下限。
4. 若为手搓 freeform，读 `docs/FREEFORM_PLAYBOOK.md`。

**判据**：能不看文档写出一个合法的最小 slide 骨架。

**失败处理**：写不出来 → 说明规范没读完，不要开始写内容。

---

## 2. 工序 1：读素材（我方缺失的第 1 道工序）

**做什么**
- 有附件：**先看，全部看**。图片附件看 UI 风格 / 版式气质 / 色彩；文档附件抽结构与关键论点；表格附件抽数字与口径。
- 多附件时逐份登记：`{文件名 → 类型 → 我将从中取什么}`。
- 附件里有框架图时，默认走「**原生重绘**」而不是贴图（见 `CONTENT_GRAPHICS.md` §5）。

**判据**：能一句话说清「这份材料要我做成什么、风格参照什么、哪些内容必须保留」。

**失败处理**：附件读不出来（加密 / 扫描件无文字）→ **立即告知用户**并给两条路：换格式重传，或我按主题自建结构。不要静默忽略附件。

**为什么这条重要**：取证样本里，用户只要说「ppt 风格参考附件 UI」「先查看附件图片 UI 风格」，成品就精准贴合；而漏读附件的成品会被打回重做。

---

## 3. 工序 2：出大纲（先同步缺口）

**做什么**
1. 建章节表：`章节名 / 承担什么 / 页数 / 每页一句话主旨`。
2. **页数先算总账**：封面 1 + 目录 1–2 + 每章（呼吸页 1 + 内容 N）+ 总结 1–3 + 封底 1。与用户要求页数对齐。
3. 页数分配表交给用户确认（或至少在报告里先声明）。
4. 发现信息缺口（数据缺、案例缺、口径不明）→ **此时就说**，不要留到交付时。

**判据**：章节表能覆盖用户要求的全部主题点；页数合计 = 目标页数 ± 5%。

**失败处理**：页数不够 → 先加章节，不要靠把单页塞满来凑数（会触发 `CONTENT_DENSITY` 反向问题与视觉灾难）。页数超了 → 砍重复论点，不砍案例。

> 取证依据：经济学样本首版仅 52 页，明确回复「尚未达到你要求的 85 页」，续做到 92 页才交付。**缺口在过程中暴露，而不是在交付时暴露。**

---

## 4. 工序 3：定设计系统（关键在「禁用清单」）

设计系统不是"选个主题"，是写出**这一本 deck 的施工图**。必须落成四段，缺一不可：

| 段 | 内容 | 示例（取证自乔布斯传式减法风格） |
|---|---|---|
| **基调** | 底色、主色、辅助色、文字色（具体 hex） | 黑底 `#1D1D1F`、白字、苹果蓝仅作点缀 |
| **字体** | 中英文字体对、字号梯度（封面/章标/正文/注释） | Montserrat 编号 + Noto Sans SC 正文 |
| **节奏** | 深—浅—深的包裹序列、章节呼吸页位置 | 封面深 → 内容浅 → 章页深 → 内容浅 → 封底深 |
| **禁用清单（负面约束）** | **本 deck 不许出现什么** | 无卡片、无 emoji、无彩虹色、无外阴影、无第三字体 |

**为什么必须写禁用清单**：只写"用什么"，做到第 50 页必然会因为"这页想强调一下"而堆东西，最后风格崩。写清"不许用什么"，才有可判定的边界。取证样本的原话就是「全篇无卡片、无 emoji、无彩虹色」。

**四种风格位（选一个当基准，再按选题微调）**

| 风格位 | 形状密度 | 卡片 | 图片 | 适用 | 取证样本 |
|---|---|---|---|---|---|
| 减法 / 杂志风 | 9–12 / 页 | 不用（`roundRect≈0`） | 大量（占文件 90%+） | 人物传记、品牌叙事、观点演讲 | 乔布斯传 9.8/页 |
| 扁平原生 | 13–19 / 页 | 适度 | 集中仪式页 | 培训课件、方法论手册、读书笔记 | GROW / PDCA / 战略桶 / 战略规划 / 经济学 / 麦肯锡 |
| 高密度信息 | 23–31 / 页 | 大量 | 极少 | 模型合集、工具书、速查手册 | 20 判断模型 31.1、思维模型 30 种 23.3 |
| 图标驱动 | 25–30 / 页 | 中等 | 大量位图 | 产品手册、功能说明 | WorkBuddy 手册 28.9 |

**判据**：写出的规格能让另一个人（或另一个自己）不问一句就复现整本视觉。

## 5. 工序 4：先做样本页（不要直接写 100 页）

**做什么**
1. 先做**前 5–6 页**：封面 + 章节页 + 2–3 种典型内容页。
2. `render` 出 PNG，**逐页看图**：密疏、层级、对齐、留白、色彩是否成立。
3. 发现设计系统要改 → **现在改**，改完重出这几页。
4. 定型后把可复用的坐标模式记下来（页眉页脚四件套、卡片网格、时间轴节距），后续批量照抄。

**判据**：这 5–6 页拼在一起像同一本书；单独看每页也站得住。

**失败处理**：样本页怎么调都别扭 → 八成是设计系统（工序 3）有问题，回退重写规格，不要靠局部微调硬救。

> 取证依据：PDCA thread「先做前 6 页、截图核对 2–3 种模板，设计系统定型后才批量」。这是长 deck 唯一不返工的做法。

---

## 6. 工序 5：分章批量（校验通过才写入）

**做什么**
1. **按章推进**，一批 10–15 页。不要一次写完 90 页。
2. 每批流程：写这批 → `lint` → 有 error 立即修 → 修到 `error=0` → 才进入下一批。
3. 每批结束报一次进度：`第 X–Y 页 OK`（内部记录即可）。

**判据**：任意时刻，已写的部分都是 `error=0` 状态。不允许"先攒着最后一起修"。

**失败处理**：某批反复修不过 → 停止推进，把这一批的失败模式归类（是文案太长？是框太小？是原型不适合这类内容？），改**模式**而不是改单页。取证样本的原话：「大部分失败是内容较长的模型核心页」——它是靠归类失败模式来收敛的。

---

## 7. 工序 6：lint 闸门（三级制）

**三级定义**（对齐取证样本「0 阻断错误 + 15 条非阻断提示」的分级口径）

| 级别 | 含义 | 处理 | 是否阻断 build |
|---|---|---|---|
| **blocker** | 硬缺陷：越界、溢出、非法取值、缺必填 | 必须修源头 | 是 |
| **advisory** | 需要人判断的疑似问题：几何近距、几何压盖、留白、密度 | 看图裁定，判定"真问题→修"或"设计意图→留痕放过" | 否 |
| **info** | 参考信息：密度统计、成本提示 | 不影响决策 | 否 |

**调用时机（三处，都要跑）**
1. **写入前**：本批 DSL 写完 → `lint` → error=0 才 write。
2. **回读后**：全文拼好后 → 再跑一遍 `lint`（跨页规则只在全文态生效：`PAGE_NUMBER` / `PLACEHOLDER_TEXT` / `LAYOUT_VARIETY` / `DENSITY_FLAT`）。
3. **交付前**：`verify --strict` 出人类可读报告，作为验收陈述的依据。

**命令**
```bash
python3 engine/cli.py lint deck.json                    # JSON 诊断，ok=false 即阻断
python3 engine/cli.py verify deck.json                   # 人类可读验收报告
python3 engine/cli.py verify deck.json --strict          # warning 也判失败（退出码 2）
python3 engine/cli.py render deck.json out_png/          # 有 error 也照常出图，用于边修边看
```

**判据**：`verify --strict` 退出码 0 是理想态；至少 `verify` 退出码 0（零 blocker）。

> 取证依据：战略规划样本自述「全稿 lint 零 error、零 warning」，是最高标准；麦肯锡样本「0 阻断 + 15 条留白提示」是务实标准。两者都成立，区别只是 advisory 的处理深度。

## 8. 工序 7：误报裁定（我方缺失的第 2 道工序）

**这是最容易被跳过、也最能体现专业度的一道。**

**做什么**
1. `lint` 报 blocker 时，**不要条件反射改 DSL**。先判断这条是"真缺陷"还是"检测误报"。
2. 判断方法：`render` 出这一页 PNG，**看图**。
3. 三种裁定结果，分别处理：

| 裁定 | 特征 | 处理 |
|---|---|---|
| **真缺陷** | 图上确实溢出 / 压盖 / 断裂 | 改 DSL（缩文案、扩框、改坐标） |
| **检测误报** | 图上完全正常（如坐标轴穿框、文字框外接框的几何假阳性） | 用语义标记豁免（`decor` / `bleed` / `role:"data-marker"`），**并在报告中记录裁定理由** |
| **设计意图** | 看着"挤"但是有意的呼吸感 / 叠层 | advisory 留痕放过，不要为了清零而破坏设计 |

4. **裁定的核心纪律：不得用 `--force` 代替裁定。** `--force` 会在产物里写入 `FreePPTForcedBuildMarker`，是"我知道有问题但我要出片"的最后手段，不是常规路径。

**判据**：每一条被放过的诊断，都能说出"为什么它不是问题"。说不出来 → 它是真的。

> 取证依据：经济学样本「少量 error 经截图核对为坐标轴穿框、文字框外接框的几何检测误报，实际渲染无遮挡」；思维模型样本「让我检查一个失败页面的具体错误，确认是否为预估溢出而非真实越界」。**对手明确知道自己的检测器会误报，并且用截图做终审。**

## 9. 工序 8：回读核对（页数与页序）

**做什么**
1. `build` 后跑 `inspect`，核对 `slides` 数量 = 规划页数。
2. 核对页码：`PAGE_NUMBER` 诊断清零，页脚显示的页码 = 实际页序。
3. 核对结构：章节呼吸页在预定位置，没有多页/漏页。
4. 手搓 deck 额外核 `picture_count == 0`。

**命令**
```bash
python3 engine/cli.py build deck.json out.pptx
python3 engine/cli.py inspect out.pptx --out structure.json
```

**判据**：`inspect` 页数 = 大纲页数；`PAGE_NUMBER` 零告警。

**失败处理**：页数不符 → 检查是否某页 `type` 写错被跳过、或批量时漏 append。**不要用"补一页空白"蒙混**。

---

## 10. 工序 9：素材核验（我方缺失的第 3 道工序）

**做什么**（有图片/外部素材时必须做）
1. 每张图：路径存在、可解码、尺寸非零。
2. 无外链残留（`http://` / `https://` 直接写在 image 节点里 → 交付到别人机器就裂）。
3. 无跨页重复（同一张图用两次以上要确认是有意的呼应）。
4. 有来源要求的图：`sources` 台账齐全，`WEB_CREDIT` 通过。
5. 图片集中度检查：图片是否都落在封面/章节页/封底？内容页出现位图要能说出理由。

**判据**：`inspect` 的 `picture_count` 与规划一致；无破图。

> 取证依据：乔布斯传样本「图片逐张核对 file_token 有效、无外链残留路径、无跨页重复」。

---

## 11. 工序 10：截图抽查（不要全信 lint）

**做什么**
1. 抽 **3–16 页**出 PNG 人工看：封面、每个章节的第一页、最密的一页、最疏的一页、封底。
2. 只看四件事：**有没有重叠 / 有没有破图 / 有没有大片空白 / 第一眼视线落点对不对**。
3. 抽查发现的问题，回头判断是不是普遍模式（是 → 全本改；否 → 局部改）。

**判据**：抽到的每一页都"可以直接拿去讲"。

**为什么必须做**：lint 是几何近似，看不到"文字压在深色渐变上发灰"、"图标太小像噪点"、"大数字水印被误读成小数点"这类只有眼睛能发现的问题。

---

## 12. 工序 11：缺口如实上报（我方缺失的第 4 道工序）

**做什么**
交付前自查三项，任一不达标就在交付说明里**明写**：

| 检查项 | 达标线 | 不达标怎么说 |
|---|---|---|
| 页数 | 达到用户要求 | 「当前 N 页，距要求的 M 页还差 K 页，原因是…，建议再补 X 章」 |
| 备注覆盖 | 100% 页面有讲稿 | 「第 X、Y 页讲稿偏薄，建议补到 40 字以上」 |
| 资料完整度 | 所有数据有来源 / 标注为示意 | 「第 X 页的行业数据为教学示意，正式使用前需替换为实际数据」 |

**铁律**：**不静默降级**。做不满就说做不满，缺数据就标"示意"，绝不编造数据填坑。

> 取证依据：经济学样本首版 52 页 → 明说未达标 → 续做；战略规划样本把虚拟案例明确标注「教学示意、数据需自填」。**专业感的来源不是完美，是诚实。**

---

## 13. 工序 12：交付自述（五段式）

固定五段，缺一段都算没交付完整：

1. **规模**：`共 N 页，分 M 章`。
2. **结构**：章节表（章名 + 页数 + 一句话）。
3. **设计规格**：主题/配色/字体/禁用清单（证明设计系统被遵守）。
4. **验收结果**：`lint` 零 blocker、`verify` 报告摘要、截图抽查了哪几页、素材核验结论。
5. **使用建议**：哪几页可直接讲、哪几页需填数据、备注怎么用。

